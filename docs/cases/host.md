# host (pseudo cases, made by the runner)

Not a disk module: the runner turns some host records (the screenshots and audio captures the guest asks for, docs/schema.md §5.1, CONTRACT §13) and its own timing of the hostspeed blocks (docs/schema.md 1.10) into pseudo cases, so they are judged and fingerprinted like guest cases (runner/amitorture/cases.py). They are not counted in the per-entry and per-module case totals.

| case | intent | rule | expected | a failure usually means |
|---|---|---|---|---|
| `shot_<tag>` | the picture of an acknowledged screenshot, on cycle-exact entries only (elsewhere the frame timing is not exact, so screenshots are kept but not compared) | the same machine, disk and seed give the same frame | always pass; the fingerprint is the PNG's sha256, so a baseline/check compares the picture | (a `check` regression: the picture changed) |
| `tone_<tag>` | the frequency of a tone the guest played (Paula `aud0`-`aud3`, sound boards), measured in the captured audio, on every entry that captured audio | the expected frequency the guest gives in the audio marks (`expect_hz`, `freq_mhz`, or clock, period and samples) and its tolerance `tol_pct` | pass within the tolerance, on the expected output channel (`side`) if given; the fingerprint is the expected frequency plus the deviation rounded to the tolerance, so it is stable on every core | fail: the wrong period or sample rate reaches the output, the wrong output channel, or a silent channel; untestable: no audio in the segment, or a tone whose length is not what the guest played (an emulator running slower than real time stretches the capture) |
| `speed_<insn>` | whether the emulator keeps real time while it executes one instruction class for 1 s of emulated time (the hostspeed module's timed blocks; docs/cases/hostspeed.md has one line per instruction) | the runner reads the guest's frame counter (mailbox heartbeat) with the host clock while the block runs: rtf = host seconds per emulated second; fail when rtf > 1.01 + 3 sigma (`SPEED_RTF_LIMIT`, sigma = the measured timing noise) and the emulation thread was at least 90 % busy (`SPEED_CPU_BOUND`: otherwise the lag came from the host, untestable) | pass when the emulator ran at most 1 % slower than real time; the fingerprint is `{st}` only, the rtf, the host CPU per emulated second and per instruction are its `timing`. **Host-relative**: compare baselines only on the same host and `--jobs`; parity never compares these (the JIT and the interpreter differ in speed by design) | fail: the emulator's code path for that instruction costs more host time than the emulated time the core charges for it (docs/cases/hostspeed.md names the path); the `why` names the host. untestable: no host samples (no mailbox, or not this runner), fewer than 3 samples in the block, or timing noise too large to tell |
