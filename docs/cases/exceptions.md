# exceptions (module 4): software exceptions and stack frames

Sources: `disk/modules/exceptions.c` (cases, expectations) and `disk/modules/exceptions_asm.s` (recording stubs, snippets; every instruction under test is `dc.w`-encoded).

**How a case runs.** The module puts its own stub on every vector 2..63 except 24-31 (interrupts). Each stub records the SR the handler starts with and its vector number. While no snippet is running, a stub chains to the runtime catch-all. `xr_call()` runs a snippet with set registers and SR (IPL 7, so there are no interrupts). An exception records the regs, 30 frame words and the SSP, then resumes after the call without an RTE, so group 0 frames are safe. In trace/log mode the stubs log {vector, handler SR, SSP, 12 frame words} and return with RTE.

**What every check compares.** The vector, the frame size (SP before minus SSP in the handler), the stacked SR (with a mask where flags are undefined), the stacked PC, the format/vector-offset word (68010+), the format $2 instruction address (68020+), and the handler SR (= stacked SR with S set and T1/T0 clear). In records, PCs and addresses are offsets from the instruction under test (`pc_off`, `addr_off`), so pass records are identical on every machine. A failure's `ctx` has the absolute address, the opcode words, the raw frame and, for traces, every logged event.

**Self-describing failures.** Every failing record's `ctx` also carries `fields` (what each key means: `*_off` = the address in the stack frame minus `insn_addr`; `addr_off` = the format $2 instruction-address field; `fv` = format<<12 | vector*4; and so on), `frame_layout` (the layout of the captured frame for its format and CPU) and `pc_rule` (the stacked-PC rule that was applied).

**Variant ids.** If a case does not apply to the detected CPU it reports `skip` with the reason, so every id is present on every run. Quick mode uses fewer random CHK inputs and fewer CCR values for TRAPcc, under the same ids.
