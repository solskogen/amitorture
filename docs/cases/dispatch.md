# dispatch (module 22): seeded random code blocks

Generated by `tools/gencode.py`, which builds the blocks and computes the expected state of each one on the host with a reference model of the integer instructions (the semantics of `tools/gen_cpu_basic.py`: M68000 PRM, MC68020/030/040/060 user manuals).

Each case is one (CPU class, seed group): 48 blocks in full mode, the first 16 in quick mode (same ids). The guest builds the initial state of a block from its seed (registers, CCR, a 256-byte data window), runs it (supervisor mode, interrupt mask 0, its own stack above the window), and compares d0-d7/a0-a7 (pointers a0-a3/a6/a7 as offsets from the window base M), the CCR (only the flags the manual defines at that point: a DIV overflow leaves N,Z undefined, ABCD/SBCD/NBCD leave N,V undefined) and the window with the expectation. Then `amt_hot_checked()` re-runs block `i mod n` for i = 0..amt_hot_reps() and compares a hash of the result with the independent expected one (interpreter vs possibly JIT-compiled execution). The first failing block index and state are saved explicitly; an iteration-0 failure is reported immediately and cannot underflow the diagnostic block index.

On a mismatch the guest bisects in-guest: it copies the block to a buffer, replaces the first opcode word of static instruction k by TRAP #15, runs it, and compares the state captured by the trap with the expected state at the first arrival at k, for each k in first-arrival order. For a failure seen only on a repeated (hot) run, each truncated copy is run many times so that a JIT compiles it too. The record is self-contained: `expect`/`got` are the full register files (d0-d7, a0-a7, ccr, ccr_mask) at the first arrival at k, plus the window bytes that differ (offset:byte); `ctx.culprit` and `ctx.k` give index, disassembly text and opcode words of the instruction executed just before k (the one that went wrong) and of k; `ctx.before` is the expected state at the first arrival at the culprit; `ctx.block_text` lists every instruction of the block (branch targets as @index); `ctx.window_base` is M (a0-a3/a6/a7 are M-relative). `tools/gencode.py --trace <case> <block>` prints the block source and the full expected trace (the state before every executed instruction).

Stack sequences include MOVE.B/W/L pushes and ordinary `(SP)+` pops, as well as MOVEM. A pop reads the old stack address before incrementing SP and releasing its bytes; byte accesses adjust A7 by two, not one. Read-modify-write operands increment only after the write.
